## PrestaShop

###  Почему PrestaShop?

Это наиболее близкий аналог opencart по:

- Простоте запуска через Docker Compose.
- Наличию UI, API и MySQL.
- Легкости написания тестов UI/API/DB

### Как развернуть?

Можно легко поднять с помощью [docker-compose](docker-compose.yml).

Описание переменных окружения - [тут](https://hub.docker.com/r/prestashop/prestashop#how-to-run-these-images).

Перед запуском тестового стенда необходимо узнать IP-адрес компьютера в локальной сети:
```shell
$ hostname -I | awk '{print $1}'

192.168.1.79
```

И затем использовать его при запуске контейнеров:
```shell
$ LOCAL_IP=192.168.1.79 docker-compose up
```

### Почему нам подходит?

#### Полноценный UI + админка

- Витрина и панель управления разделены.
- Можно тренироваться на реальных сценариях: фильтры, корзина, заказы, товары.

#### REST API

Можно практиковать

- Авторизацию через API-ключ
- CRUD для ресурсов: products, customers, orders и др.

#### Подключение к MySQL

- Можно делать проверки из БД (e.g. товар создан через UI → есть в БД).
- Прямая работа с базой

#### Легко запускается в Docker

- Официальный образ.
- Устанавливается за 1–2 минуты.
- Настраивается через переменные окружения.

####  Подходит для задач любого уровня

- UI: Selenium, Playwright, Selenide и др.
- API: requests, curl. 
- DB: pymysql, psql.

### Тело POST/PUT запросов должно быть в XML?

Да, PrestaShop Webservice API по умолчанию работает с XML, и даже если запросы можно получать в JSON, 
тело POST/PUT запросов **должно быть** в XML.

То, что PrestaShop использует XML для POST/PUT запросов - не минус, а возможность расширить обучение.

### Почему XML в API — это плюс в учебном контексте?

#### Расширяет технический кругозор студентов

Большинство новичков сталкиваются только с JSON и REST. Работа с XML:

- Показывает альтернативу JSON, которая всё ещё используется в реальных системах (SOAP, старые CRM/ERP, банковские API).
- Учит читать и писать иерархичные структуры с атрибутами и пространствами имён.

#### Учит использовать инструменты сериализации/десериализации

- Работа с `lxml`, `ElementTree`, XSD-схемами — это ценная практика.
- Отличная возможность научиться: создавать XML «вручную», парсить ответ в дерево, модифицировать XML на лету.

#### Формирует привычку разбираться в чужом формате

При работе с PrestaShop студенты:

- Учатся получать шаблон XML по `/api/resource?schema=blank`.
- Видят как PrestaShop ожидает структуру.
- Осознают важность правильного порядка, вложенности и атрибутов.

Это близко к опыту в legacy-системах и сложных API-интеграциях, где формат строго определён.

#### JSON при GET - бонус

Когда получаем данные из API в JSON (через заголовок `'Output-Format: JSON'`), студенты:

- Видят разницу между XML ⇄ JSON.
- Учатся переключать формат запроса/ответа с помощью заголовков.
- Могут тренировать привычные инструменты (например, `json.loads()` или **Postman**).
- Могут удобно валидировать ответ и писать автотесты.

#### Подход с объединением JSON-чтения + XML-записи

- Реалистичен (встречается в старых API).
- Многоуровневый - задействует больше инструментов и скиллов.
- Развивает гибкость и адаптивность.
